# Rift24

**Rift24 finds what the 24/7 rToken market hasn't priced yet.**

It measures how much overnight information is already priced into 24/7 [Bitget rTokens](https://www.bitget.com/campaigns/bitget-rtoken) before the U.S. cash market opens — and only acts when meaningful residual remains after costs.

> **Paper/backtest only. No live-money trading.** No API keys are needed or used; the code cannot place an order.

**Live demo:** [rift24.vercel.app](https://rift24.vercel.app) — static build reading the same frozen fixture as `bash scripts/serve.sh` below. **Source:** [github.com/Megacollins/rift24](https://github.com/Megacollins/rift24).

- **Track:** Alpha Factory — Quantitative Strategies
- **Sub-theme:** After-Hours Information Pricing
- **Hackathon:** Bitget AI Base Camp Hackathon S2 (deadline 27 Sep 2026, 23:59 UTC+8)

## Target user

Crypto-native Bitget retail / lower VIP traders with approximately $3k–$25k capital who hold 2–10 liquid rTokens, such as rNVDA, rTSLA, rQQQ, rSPY, rMETA, rAAPL, rMSFT, rAMZN, rGOOGL and rAMD, and who sleep through the U.S. cash session rather than running a professional stat-arb book.

## Core hypothesis

U.S. cash equities close (16:00 ET) and reopen (09:30 ET). rTokens trade 24/7, so information arriving in the *void* is priced by the rToken first. Two readings:

1. **H1 (pre-specified, from the brief):** rTokens *over-move* in the void, so **fading** large void moves (`signal = −R_rtoken`) earns positive risk-adjusted returns after costs. → *Tested first, as the primary backtest.*
2. **The residual view:** whatever the answer, `residual = implied next cash move − move already printed − costs` tells you whether anything is left to trade. Rift24 acts only when it is at least 2× cost, and otherwise says **DO NOTHING**.

`R_cash` (the realised gap) is used only **after** the open, for outcomes and the autopsy. It can never reach a decision.

## Strategy logic

```
prior cash close ── rToken trades through the void ── DECISION ── entry ── exit ── cash OPEN
16:00 ET (base)                                        09:15 ET*   next bar   last pre-open bar   09:30
                                                       (* pre-specified; an exploratory study moves it earlier)
```

`R_rtoken` = rToken price at decision / rToken price at the prior cash close − 1. Decisions, entries **and exits** all happen while cash is closed — nothing is opened or closed in the regular session.

| Gate | Rule |
|---|---|
| 1 | Cash market must be closed at decision time |
| 2 | Ticker must be in `data/allowlist.json` |
| 3 | \|void move\| ≥ 2 × total cost (cost-based, configurable, **not optimised**) |
| 4 | Costs priced: 8 bps round-trip taker-style haircut + spread haircut (observed if available, else **+4 bps ESTIMATED fallback**) |
| 5 | Expected edge ≥ 2 × cost, estimated **only from past sessions** (≥ 30 observations, significance test); if it cannot be established → DO NOTHING |
| 6 | Data fresher than 15 minutes (live mode) |
| 7 | Max single-name notional 20% of the simulated book |
| 8 | Valid close→open void session |

Stances: **FADE** (trade against the void move: over-priced), **ADD** (join it: under-priced), **FLATTEN** (the pre-open exit), **DO NOTHING**. The pre-specified rule only ever produces FADE; the exploratory two-sided variant may also ADD.

Baselines: **A** DO NOTHING, **B** ALWAYS FADE (gates 1, 2, 3, 8 only). Rift24 beats B only by standing down: it earns 0 where always-fade loses, because there is no positive-return fade to gate. It does not find a profitable trade here and does not pretend to — that is reported rather than hidden.

## How to run — fully offline

Python 3.11+.

```bash
pip install -r requirements.txt        # tzdata (+ pytest for the tests)
python -m scripts.run_backtest         # prints the metrics table; writes reports/backtest.json and reports/thesis.md
python -m scripts.build_demo_state     # pre-renders data/demo_state.json for the static desk
python -m scripts.render_docs          # regenerates SUBMISSION.md and the README results block from the JSON
bash scripts/serve.sh                  # then open http://localhost:5210/app/landing/  (or /app/ for the desk directly)
python -m pytest -q                    # 110+ tests
```

`app/landing/` is the pitch page — thesis, the honest H1-rejected finding, and key numbers, all read live from `data/demo_state.json` (never hand-typed, so it can't drift from the real backtest) — with links into the desk, including deep links (`../index.html#backtest`, `#replay`) that open straight to that tab. The desk itself (`app/index.html`) is static HTML/CSS/JS (no build step, no backend, no auth, no database) and is responsive from 320 px phones to 2560 px displays: no page-level horizontal scroll at any width, the residual/decision/outcome tables become stacked cards below 900 px (Stance stays in each card's header), the desk goes side-by-side only ≥ 1380 px where the table fits unscrolled, and charts are drawn in real pixels so text stays ≥ 10 px. Both pages read `data/demo_state.json`, or the embedded copy `app/demo_state.js` if opened from `file://`. The same fixtures drive the backtest, the demo and the replay — no external API is required at any point.

**Demo path (3 minutes):** *Landing* (thesis + honest H1-rejected result at a glance) → *Desk* (clock: U.S. cash CLOSED / rTOKENS TRADING 24/7 → headline → residual table with DO NOTHING on the attractive-looking names → click a row) → *Backtest* (IS/OOS, Sharpe, Sortino, MDD, OOS/IS ratio, rolling Sharpe, stand-down, baselines) → *Weekend replay* (Run replay: close → weekend event → rToken move → decision → open → outcome).

## Forward test (pre-registered)

The 04:00 ET result is a hypothesis. To turn it into evidence, the rule and model are **frozen and hashed** (`data/forward/frozen_model.json`), the success criterion is fixed in [`data/forward/PREREGISTRATION.md`](data/forward/PREREGISTRATION.md) *before* any forward data exists, and three append-only steps collect real out-of-sample observations:

```bash
python -m scripts.forward_test snapshot   # ~04:02 ET Mon-Fri: logs the frozen rule's stance for all 10 rTokens + OBSERVED spreads
python -m scripts.forward_test settle     # after 09:35 ET: logs the realised cash gap and net P&L
python -m scripts.forward_test report     # running summary; verdict stays INCONCLUSIVE until 30 trades on 15 days
```

The model is never refit on forward data, rows are never edited, and a late snapshot trips the freshness gate rather than pretending. Replaying 21 Sep against the live API reproduces the backtest's decisions and P&L exactly (rAMD +212 bps, rMETA −29 bps net). **No forward results exist yet** — the first decision is 22 Sep 04:00 ET.

## Backtest methodology

- **Sessions:** prior regular close (16:00 ET, 13:00 on early closes) → next regular open (09:30 ET) from `rift24/calendar.py` (holidays 2025–27, DST-safe); the calendar's trading days are asserted equal to the days Yahoo has bars for.
- **No look-ahead:** the decision function accepts a `PreOpenView` that has no cash-open, entry or exit field. The priced-in model is refit walk-forward on sessions whose outcome was fully known before the decision. `tests/test_no_lookahead.py` rewrites every post-decision input and asserts no decision changes.
- **Fills:** entry at the open of the 15-minute bar after the decision; exit at the close of the last bar before the open. Sizing: equal weight over the day's trades, ≤ 20% per name, gross ≤ 100% (unlevered).
- **Missing data:** 15-minute bars with no trades are absent (mostly weekends). Prices carry forward ≤ 4 bars; gate 6 rejects > 15-minute-old prices for Rift24; sessions whose entry/exit bar has no trade or that lack a cash bar are excluded for every strategy (0 in the scored window).
- **Split:** chronological 60/30; nothing is fitted in-sample beyond the walk-forward beta, so IS and OOS are scored by the identical rule.
- **Robustness (not tuning):** cost ×0 / 20 bps fee, exits 15/30/60 min after the open, gate 3 at 1×/4× cost, and a full sensitivity table in `reports/backtest.json`. The base configuration was fixed from the brief before any result was seen.

## Metrics methodology

Per-session book returns (sessions without a trade contribute 0, so stand-down is inside every denominator). **Sharpe** = mean/std(ddof 1) × √252, rf 0, with a Lo (2002) standard error reported. **Sortino** = mean / downside deviation × √252, downside = min(r, 0) over *all* sessions, target 0. **Max drawdown** on the compounded equity curve. **Turnover** = (entry + exit notional) / book. **Win rate** on net trade P&L. **OOS/IS ratio** with the alert `OOS Sharpe < 0.5 × IS Sharpe` (reported as not meaningful when IS Sharpe ≤ 0). **Rolling 30-day Sharpe** over trailing 30 calendar days (≥ 15 sessions). **Stand-down rate** = share of sessions/symbol-sessions with no trade. Undefined metrics are `null`/"n/a", never zero.

## Cost assumptions

8 bps round-trip taker-style haircut (**ESTIMATED**, the brief's default) + 4 bps after-hours spread haircut (**ESTIMATED** fallback; historical bid/ask is not public, so it is never presented as observed) + 0 bps extra slippage = 12 bps. The exchange's own published spot taker fee is **10 bps per side (20 bps round trip, OBSERVED)** — worse than the default — and is run as a sensitivity.

## LLM role

The LLM is **not** the strategy. It may only (1) map an event/headline to an allow-listed ticker and (2) write a short explanation. It is off by default (the rule-based mapper in `rift24/events.py` is the default), its output is validated (unknown tickers and anything reading like a trading instruction are rejected), and the quantitative engine never imports it. It does not size, time or decide any trade.

## Limitations

- ~90 days, ~13 weekends, one regime; rTokens listed on 2026-06-01. The null result is not evidence about other regimes.
- The void is measured against the *regular session*. U.S. pre-market (from 04:00 ET) and after-hours venues already price information, and Bitget states rToken prices are linked to U.S. exchange liquidity — consistent with the finding that the move is ≈ fully priced by 09:15 ET.
- Spread is assumed; depth and fill size at overnight hours are not observed. Bitget-reported rToken volumes are implausibly large relative to the cash markets, so volume is not used as evidence of liquidity.
- Spot rTokens cannot be shorted: the FADE/SELL leg needs a short-capable venue.
- The **exploratory** two-sided residual rule was found *after* the pre-specified test failed, on the same sample, with the decision time chosen from a 5-point grid; its out-of-sample numbers are not clean and rest on a dozen trades. It is a hypothesis for a forward test, not a claim of edge.
- Event board: the three SOURCED items were located by web search and read on 2026-09-21 and are context only, never claimed causes; two items are ILLUSTRATIVE and labelled as such. The live Bitget Signal feed is TARGETED, not built. A GetAgent Playbook port is not done.
- **A design correction is disclosed:** the first draft exited 15 minutes *after* the open; inspecting the weekend replay showed that bar carries regular-session price action, so exits were moved before the open and everything recomputed (the old exit is a sensitivity row).
